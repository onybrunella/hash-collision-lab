# Split 2 – Verifying real collisions (Sandra)

Goal: show that MD5 and SHA-1 are broken by their **design**, using real collisions on the full functions, and that the same files do **not** fool SHA-256 or SHA3-256.

---

## 1. Run the experiment

From the root of the repository, with the virtual environment active:

```bash
python src/exp2_verify_collisions.py
```

- Prints one line per pair and hash function: pair name, hash function, same hash (True/False).
- Saves the full table, with the hashes, in `results/exp2_collisions.csv`.
- Creates the `_suffix` files in `data/` each time it runs (not committed).

## 3. Generating the MD5 collision (fastcoll)

- Tool: fastcoll v1.0.0.5 by Marc Stevens, Windows executable from https://marc-stevens.nl/research/hashclash/
- Kept outside the repository (not committed).
- `prefix.txt` contains one line of text; both output files start with it.

Command (PowerShell), timed with `Measure-Command`:

```powershell
Measure-Command { .\fastcoll.exe -p prefix.txt -o md5_a.bin md5_b.bin }
```

Check: `certutil -hashfile md5_a.bin MD5` and `certutil -hashfile md5_b.bin MD5` give the same hash
(`f11b51b1b72ee415e020d5c34de9da09` for our pair).

## 4. What the script does

| Function | Job |
| --- | --- |
| `hash_file(path, algorithm)` | Returns the hash of a file as hex text (`hashlib`) |
| `compare_pair(name, path_a, path_b)` | Checks the two files are different, then compares them with the 4 hash functions; returns one row per function |
| `add_suffix(path, suffix, new_path)` | Copies a file and adds the same bytes at the end |
| `save_csv(rows, path)` | Writes the results table to a CSV file |
| `main()` | Makes the suffix copies, compares the 4 pairs, prints and saves the results |

Hash functions tested: `md5`, `sha1`, `sha256`, `sha3_256` (list `HASH_FUNCTIONS` at the top of the file).

---

## 5. Results

| Pair | MD5 | SHA-1 | SHA-256 | SHA3-256 |
| --- | --- | --- | --- | --- |
| shattered | different | **same** | different | different |
| fastcoll | **same** | different | different | different |
| shattered + suffix | different | **same** | different | different |
| fastcoll + suffix | **same** | different | different | different |

- Each collision fools only the function it was built for.
- SHA-256 and SHA3-256 are never fooled.
- Adding the same suffix to both files keeps the collision: after the colliding blocks both files are in the same internal state, and Merkle-Damgård processes the rest identically (Section II-C of the Part 1 report).
